# Skill Registry — Implementation Reference

## Architecture

```text
skill-registry/
├── cmd/
│   ├── skill-registry/   # Registry server entry point
│   └── skforge/          # Registry-administration CLI
├── internal/
│   ├── api/              # HTTP handlers, routing, response DTOs
│   ├── auth/             # Token authentication + scope middleware
│   ├── config/           # YAML config + env overrides
│   ├── metadata/         # SQLite models, repository, SkillManifestFromSpec mapper
│   ├── observability/    # slog structured logging, request-ID middleware
│   ├── packaging/        # Skill package builder (tgz/zip → spec.PackageManifest)
│   ├── registry/         # Core orchestration (publish, download, governance)
│   ├── storage/          # Content-addressable blob storage (SHA-256)
│   └── validation/       # Package validator (profiles: default / strict / publish)
└── pkg/
    └── client/           # Go client library
```

## Responsibility Boundary

| Tool | Owns |
| --- | --- |
| **SkillForge / `skforge`** | Registry server, API, immutable storage, metadata, governance, auth, audit |
| **`skpm`** | validate, package, publish lifecycle, install, lock, update, verify, `agent-skills.yaml` |
| **`skcr`** | scaffold, bake, render, `agentic.bake.yaml` |

`skforge` is a registry-administration CLI. Consumer lifecycle (`install`, `lock`, `verify`) belongs to `skpm`.

## sklib Integration

SkillForge uses `github.com/domehahn/sklib` (workspace replace) throughout:

| Package | Used for |
| --- | --- |
| `sklib/spec` | `spec.Skill` (skill.yaml model), `ValidateSkillName`, `ValidateNamespace`, `IsSemVer`, `IsKnownPlatform`, `Platform` |
| `sklib/registryapi` | `CapabilitiesResponse`, `ResolveResponse`, `PublishResponse`, `SearchResponse`, `SkillInfoResponse`, `SkillVersion` |
| `sklib/packageio` | `IsForbiddenPackagePath`, `PackageManifest` |
| `sklib/validate` | `ValidatePackageManifest` (publish profile) |

## Validation Profiles

| Profile | Required files | Additional checks |
| --- | --- | --- |
| `default` | SKILL.md | — |
| `strict` | SKILL.md, VERSION, skill.yaml, CHANGELOG.md | version match, entrypoint exists |
| `publish` | SKILL.md, VERSION, skill.yaml, CHANGELOG.md, **manifest.json**, **checksums.txt** | manifest.json parsed as `spec.PackageManifest`, validated via `validate.ValidatePackageManifest`, name/version cross-check against skill.yaml |

### Skill Name Rules

Canonical kebab-case via `spec.ValidateSkillName`: `^[a-z0-9]+(?:-[a-z0-9]+)*$`

- Valid: `gitlab-policy-reviewer`, `my-skill`, `toolname`
- Invalid: `my.skill`, `my_skill`, `skill-`, `my--skill`

No length limit enforced server-side.

### Path Security

`packageio.IsForbiddenPackagePath` covers absolute paths, traversal (`../`), `.git`, `.env`, `node_modules`, `.venv`, `__pycache__`, and private-key extensions (`.pem`, `.key`, `.pfx`, `.p12`). Backslash paths rejected locally.

## Package Format

Packages are ZIP or TGZ archives. Canonical layout (publish-grade):

```text
<skill-name>/
├── SKILL.md           required, non-empty
├── VERSION            required, SemVer without v-prefix
├── skill.yaml         required, parsed as spec.Skill
├── CHANGELOG.md       required, must contain entry for VERSION
├── manifest.json      required (publish), spec.PackageManifest (generated by skpm/skforge)
├── checksums.txt      required (publish), SHA-256 per file
└── README.md          recommended
```

`manifest.json` is generated by `skpm package` or `skforge package` — it carries `spec_version`, `packaged_by`, `packaged_at`, `files`, and `compatible_with []Platform`.

## Publish Flow (server-side)

1. Parse Content-Type → `packageType` (zip / tgz)
2. `registry.Publish(namespace, name, version, data, packageType)`
3. `spec.ValidateSkillName` + `spec.ValidateNamespace` + `ValidateVersion`
4. `Validator.ValidatePackageWithProfile(data, packageType, ProfilePublish)`
   - reads `skill.yaml` → `*spec.Skill`
   - reads `manifest.json` → `spec.PackageManifest`, validates, cross-checks
   - checks `checksums.txt` presence
5. Immutability check — version must not already exist
6. `storage.Store` → SHA-256 content-addressed blob
7. `metadata.CreateOrUpdateSkill` + `metadata.CreateVersion` (via `SkillManifestFromSpec`)
8. `repo.SetDistTag("latest", ...)`
9. Mirror to artifact table
10. Audit log entry

## Data Models

```text
metadata.Skill           DB record for a skill (name, namespace, tags, owners)
metadata.SkillVersion    DB record for a version (digest, manifest, yank/deprecate status)
metadata.SkillManifest   DB model: local struct with []string CompatibleWith
spec.Skill               Canonical package model: []Platform CompatibleWith (no Compatibility legacy field)
metadata.SkillManifestFromSpec(*spec.Skill) *SkillManifest   — the only mapping point
```

## Authentication

Token-based with scopes: `read`, `write`, `delete`.

Config:

```yaml
auth:
  enabled: true
  tokens:
    - name: ci
      token_env: SKILL_REGISTRY_CI_TOKEN
      scopes: [read, write]
    - name: admin
      token_env: SKILL_REGISTRY_ADMIN_TOKEN
      scopes: [read, write, delete]
```

## Running

```bash
cd skill-registry
make build
./bin/skill-registry                   # uses config.yaml or defaults
```

Environment overrides: `SKILL_REGISTRY_ADDR`, `SKILL_REGISTRY_DATA_DIR`, `SKILL_REGISTRY_DB_PATH`, `SKILL_REGISTRY_MAX_PACKAGE_SIZE_MB`, `SKILL_REGISTRY_AUTH_ENABLED`.

## Admin CLI (skforge)

`skforge` is for registry-administration tasks only:

```bash
skforge token create --name ci-publish --scopes write
skforge skills list
skforge skills deprecate default/gitlab-policy-reviewer 1.4.0 --reason "superseded"
skforge skills yank default/gitlab-policy-reviewer 1.3.0 --reason "critical bug"
skforge package ./my-skill --output-dir dist   # convenience; canonical tool is skpm
skforge publish dist/my-skill-1.0.0.tgz --registry http://localhost:8080
```

Consumer lifecycle (`add`, `lock`, `install`, `update`, `verify`) is handled by **`skpm`**, not `skforge`.
